# ERP系统上线前用户测试 - Product Requirement Document

## Overview
- **Summary**: 对ERP系统进行全面的上线前用户测试，覆盖所有核心业务模块，通过多轮测试快速迭代修复系统问题，确保系统达到上线标准。
- **Purpose**: 验证系统功能完整性、业务流程正确性、用户体验友好性、数据一致性，确保系统能够稳定运行并满足用户需求。
- **Target Users**: 系统管理员、业务操作人员、财务人员、仓库管理员。

## Goals
- 执行三轮完整的系统测试，覆盖所有核心功能模块
- 验证所有关键业务流程的正确性
- 发现并修复所有阻碍上线的P0级别问题
- 确保数据一致性和系统稳定性
- 提供完整的测试报告和上线决策建议

## Non-Goals (Out of Scope)
- 不进行大规模性能压力测试（后续单独测试）
- 不进行安全漏洞扫描（后续单独测试）
- 不涉及新功能开发（仅修复现有问题）
- 不进行数据库架构调整（除非发现严重问题）

## Background & Context
- 系统已完成初步功能开发和数据流梳理
- 已有完整的测试数据（10客户、20产品、5供应商）
- 之前已完成一轮代码审查测试，修复了7个P0问题
- 测试环境：H2内存数据库 + Spring Boot后端 + Vue 3前端
- 支持Docker Compose部署

## Functional Requirements

### FR-1: 用户登录与权限测试
- 验证管理员登录功能正常
- 验证各角色权限控制正确
- 验证登录安全机制（密码加密、JWT令牌）

### FR-2: 基础数据管理测试
- 验证客户CRUD操作完整
- 验证产品CRUD操作完整
- 验证供应商CRUD操作完整
- 验证原材料CRUD操作完整
- 验证分类筛选功能正常

### FR-3: 销售业务流程测试
- 验证报价单创建和详情查看
- 验证报价单转订单功能
- 验证销售订单创建、编辑、状态流转
- 验证订单明细验证逻辑
- 验证成本利润自动计算
- 验证信用额度检查和占用/释放
- 验证应收款自动生成

### FR-4: 采购业务流程测试
- 验证采购订单创建和编辑
- 验证完整收货和部分收货
- 验证入库进度更新
- 验证应付款自动生成
- 验证库存扣减逻辑

### FR-5: 库存管理测试
- 验证入库单创建和执行
- 验证出库单创建和执行
- 验证库存预警显示（≤10件）
- 验证库存数量统计
- 验证仓库库存查看

### FR-6: 财务核销测试
- 验证应收款收款核销
- 验证应付款付款核销
- 验证paymentDate和paymentMethod保存
- 验证状态流转（unpaid→partial→paid）
- 验证财务数据一致性

### FR-7: 表单验证和错误处理
- 验证必填字段验证
- 验证数据格式验证
- 验证错误提示友好性
- 验证空状态处理

## Non-Functional Requirements
- **NFR-1**: 页面响应时间<3秒（95%请求）
- **NFR-2**: 系统启动时间<2分钟
- **NFR-3**: 无浏览器控制台错误
- **NFR-4**: 移动端适配良好（响应式布局）
- **NFR-5**: 错误消息清晰易懂

## Constraints
- **Technical**: 使用现有H2内存数据库进行测试
- **Business**: 测试数据使用现有data.sql，不删除或修改已准备的测试数据
- **Time**: 完成时间控制在4个测试轮次内
- **Dependencies**: 依赖之前已修复的P0问题保持正常

## Assumptions
- [Assumption 1]: Docker环境可用，能正常启动服务
- [Assumption 2]: 浏览器环境正常，能正常访问前端页面
- [Assumption 3]: 测试数据已正确加载
- [Assumption 4]: 用户能够配合提供登录凭据（CLG/258258258）

## Acceptance Criteria

### AC-1: 登录功能验证
- **Given**: 系统已启动，访问登录页面
- **When**: 输入正确的用户名密码（CLG/258258258）并点击登录
- **Then**: 成功登录并跳转到首页
- **Verification**: `programmatic`
- **Notes**: 验证登录状态保持、JWT令牌生成、自动登录等

### AC-2: 客户管理功能验证
- **Given**: 已登录系统，进入客户管理页面
- **When**: 执行客户列表查看、详情查看、新增、编辑操作
- **Then**: 所有操作正常，数据正确保存
- **Verification**: `programmatic` + `human-judgment`

### AC-3: 销售订单完整流程验证
- **Given**: 已有测试客户和产品数据
- **When**: 从报价单创建→转订单→审核→生产→发货→完成→收款核销
- **Then**: 整个流程顺利完成，数据正确，状态正确流转
- **Verification**: `programmatic` + `human-judgment`

### AC-4: 库存预警功能验证
- **Given**: 库存中有≤10件的产品
- **When**: 查看库存页面
- **Then**: 显示红色预警标签和低库存统计
- **Verification**: `human-judgment`

### AC-5: 财务核销功能验证
- **Given**: 有待核销的应收款和应付款
- **When**: 执行收款和付款核销操作，填写paymentDate和paymentMethod
- **Then**: 核销成功，数据正确保存，状态正确更新
- **Verification**: `programmatic`

### AC-6: 表单验证功能验证
- **Given**: 在新增页面未填写必填字段
- **When**: 点击保存
- **Then**: 显示清晰的错误提示，阻止提交
- **Verification**: `human-judgment`

### AC-7: 数据一致性验证
- **Given**: 完成一轮业务操作
- **When**: 检查前端显示数据和后端数据库数据
- **Then**: 数据一致，没有数据丢失或错误
- **Verification**: `programmatic`
