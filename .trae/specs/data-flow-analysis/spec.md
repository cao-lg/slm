# 项目数据流梳理与检查计划

## Why
当前ERP系统已完成基础功能开发，但尚未全面梳理各模块间的数据流向关系。需要确保从前端表单输入 → API传输 → 后端处理 → 数据库存储 → 前端展示的完整数据流逻辑正确，数据一致性和业务规则完整。

## What Changes

### 数据流梳理
- 全面梳理客户管理模块数据流
- 全面梳理产品/原材料管理模块数据流
- 全面梳理销售模块数据流（报价单 → 销售订单 → 发货单）
- 全面梳理采购模块数据流（采购申请 → 采购订单 → 入库单）
- 全面梳理财务模块数据流（应收/应付/费用）
- 全面梳理库存模块数据流
- 全面梳理生产模块数据流

### 数据流检查要点
- 表单数据验证规则检查
- API接口参数校验检查
- 后端业务逻辑正确性检查
- 数据库事务完整性检查
- 前后端字段一致性检查
- 状态流转逻辑正确性检查
- 数据关联关系正确性检查

### 项目检查计划建立
- 建立功能模块检查清单
- 建立数据一致性检查清单
- 建立业务流程检查清单
- 建立接口规范检查清单
- 建立安全规范检查清单

### 项目更新
- 修复发现的数据流问题
- 完善业务逻辑漏洞
- 补充缺失的数据验证
- 优化数据流转性能

## Impact

### Affected specs

- business-process-alignment（业务流程对齐）
- erp-system-v2（ERP系统基础）

### Affected code

- 后端：所有Controller层API接口
- 后端：所有Entity实体类
- 前端：所有表单组件
- 前端：所有列表组件
- 数据库：所有表结构和约束

## ADDED Requirements

### Requirement: 数据流梳理完整性
系统 SHALL 提供完整的数据流文档，记录所有模块的数据输入、处理逻辑、数据输出。

#### Scenario: 客户管理数据流
- **WHEN** 用户在客户管理页面创建/编辑客户
- **THEN** 验证数据 → 调用API → 后端处理 → 数据库存储 → 返回结果 → 前端更新

#### Scenario: 销售订单数据流
- **WHEN** 用户从报价单生成销售订单
- **THEN** 复制报价明细 → 价格计算 → 库存检查 → 订单创建 → 明细创建 → 返回结果

#### Scenario: 采购订单数据流
- **WHEN** 用户创建采购订单并关联原材料
- **THEN** 选择供应商 → 选择原材料（支持多供应商）→ 价格获取 → 订单创建 → 明细创建 → 入库跟踪

### Requirement: 数据流逻辑正确性
系统 SHALL 确保所有数据流环节的逻辑正确，数据验证完整，事务处理安全。

#### Scenario: 数据验证完整性
- **WHEN** 前端提交任何表单数据
- **THEN** 执行客户端验证 → 后端二次验证 → 业务规则校验 → 存储验证

#### Scenario: 事务完整性
- **WHEN** 执行涉及多表操作的数据处理
- **THEN** 开启事务 → 执行主表操作 → 执行明细表操作 → 提交事务 → 异常回滚

### Requirement: 项目检查清单
系统 SHALL 提供完整的项目检查清单，覆盖所有功能模块和业务场景。

#### Scenario: 检查清单执行
- **WHEN** 执行项目检查
- **THEN** 按清单逐项检查 → 记录问题 → 修复问题 → 复验通过

## MODIFIED Requirements

### Requirement: 数据字典对齐（扩展）
现有数据字典对齐规范扩展，增加数据流维度检查。

## REMOVED Requirements

无

## 风险与约束

### 风险
1. 数据流梳理可能发现较多问题，需要分配足够时间修复
2. 部分数据流涉及第三方集成，需要模拟测试
3. 状态流转逻辑复杂，可能存在边界情况

### 约束
1. 必须保证现有功能不受影响
2. 数据库结构不能做破坏性变更
3. API接口需要保持向后兼容
